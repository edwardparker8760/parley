## What it is

Two AI agents negotiate price, quantity and terms for bulk inference capacity.
Each acts for a human owner who set hard limits in advance. When they converge,
the deal settles in USDC on Arc. When no overlap exists, both walk away and each
reports which limit stopped it.

The claim the project exists to make: **owner limits are enforced in arithmetic,
not in a prompt.** The LLM proposes; arithmetic disposes.

## The safety property, and how it is enforced

Four independent mechanisms, deliberately not one:

1. **`computeFeasibleBand` is pure.** No clock, no randomness, and critically
   **no access to any free text**. That last property is why no prompt can move
   a band: the function that decides what is legal cannot read language.
2. **The clamp** inside the agent forces every proposal into that band.
3. **An independent egress guard** on the message bus re-derives the band and
   rejects anything outside it. It shares only the pure band function with the
   clamp, so a single bug cannot defeat both. It throws rather than filtering,
   because a breach means the clamp is broken.
4. **The round cap lives in the turn loop, outside both agents.** A hostile
   agent that never accepts and never walks away still terminates.

The LLM sits **downstream of the band and upstream of the clamp**, and is
restricted to a 2% window around the deterministic pick. Its number is
re-validated twice after it is chosen.

## LLM layer

- Provider is Google Gemini `gemini-3.5-flash-lite` behind a factory. Swapping
  the provider mid-build changed **zero** tests in the injection suite.
- Six outcome branches, all logged: `ACCEPTED`, `OUT_OF_BAND` (discard the
  number, keep the words), `SCHEMA_INVALID`, `TIMEOUT`, `ERROR`, `LLM_OFF`.
- Every consultation is written to `llm_invocations` with the prompt hash, the
  raw response, and the price arithmetic refused.
- **All three scenarios run live against Gemini** (`docs/llm-negotiation-runs.md`):
  A 17 calls / 70.7s, B 23 / 96.5s, C 16 / 65.7s, zero rate-limit failures under
  pacing. Tapes recorded; replay reproduces each run identically in under a
  second, which is why the demo runs from tape rather than live.
- The LLM moves the settled price by about 2 micro-USDC and rewrites every
  rationale. Scenario C still walks away with the model on.

## Settlement

| Mode | State |
|---|---|
| `local-stub` (default) | Working, measured at 815ms, badged SIMULATED everywhere |
| `arc-x402` | **Implemented and tested offline; never run with real money** |

The real path needed a piece the plan did not name: `GatewayClient.pay(url)` pays
an HTTP resource that answers 402, and two agents in one process have nothing to
pay. So `packages/seller-service` exists: it prices each request from the
seller's **own** copy of the deal row and rejects a mismatched terms hash with
409 before quoting a price, so a buyer can neither underpay nor detach a payment
from its negotiation.

`settle()` returns `PENDING`, never `SETTLED`. Circle batches and exposes no
flush, so an accepted authorisation is not a confirmed transfer.

**Blocked on one thing only:** the buyer wallet `0x38D6faC8493cd60C120fa0629A19713606d64F38`
has zero balance. Faucet funding is a browser flow.

## Dashboard

One screen at 1920x1080, no page scroll, verified in a real browser across all
three scenarios. Convergence chart with audience-only reservation lines and ZOPA
shading, transcript with clamp and LLM badges, owner limits with override
counters, settlement or walk-away.

Live and replay deliver an **identical payload**, so every panel is written once.
SSE reads the view from the same database handle the negotiation writes to, which
makes browser state provably a function of the ledger.

`?negotiation=<id>` replays any completed run from the ledger with no live
process, including runs recorded from the CLI.

## Bugs this work caught

Worth recording, because each was found by verification rather than by review:

1. **A clean clone reported a vacuous pass.** `pnpm test` ran `node --test` over
   an absent `dist`: zero tests, exit 0, green. A judge would have seen a green
   run that verified nothing. Found by the phase 08 clean-clone test.
2. **Scenario B's outcome depended on a timestamp.** The jitter seed was the
   negotiation id, and the dashboard mints a fresh id per run, so B flipped
   between settling and walking away. Fixed with `seedKey`.
3. **A layout bug would have hidden the settlement panel.** Five panels into four
   grid cells auto-placed the last into an implicit row that `overflow: hidden`
   ate.
4. **The README credited Circle Developer-Controlled Wallets**, which the phase
   01 spike had already proven are not in the payment path.
5. **A fabricated latency report** (mean 0.00s from 18 failed calls) was caught
   and deleted; that incident produced `docs/verification-must-not-silently-noop.md`.
6. **A red-green colour-blind viewer could not tell SETTLED from WALKED_AWAY.**
   The original palette put success on `#3fb950` and failure on `#f85149`, which
   measure deltaE **9.0** apart under simulated deuteranopia: a collision, on the
   most important distinction on the screen. It had been on screen since phase 07
   and looked fine to everyone who looked at it, because everyone who looked at
   it could see red and green. Found only because the design re-skin required
   proving the new palette was safe, which meant measuring the old one first.
   Fixed by `packages/theme`, whose status palette measures 21.9 at worst.
   Same lineage as the other five: eyeballing agreed, arithmetic disagreed.
